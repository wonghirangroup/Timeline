# อัปเดตคู่มือแอดมิน (/manual) ให้ตรงกับหน้าจอจริง

คู่มือมี 3 ส่วนที่ต้องตรงกันเสมอ: **ข้อความ** · **ภาพหน้าจอพร้อมวงเลข** · **รายการเลขอธิบายใต้ภาพ** ถ้าแก้หน้าจอแล้วไม่ตาม คู่มือจะสอนผิดและวงเลขจะชี้ผิดปุ่ม

| ส่วน | ไฟล์ |
|---|---|
| เนื้อหา (หมวด → หัวข้อ → ขั้นตอน/ภาพ/หมายเหตุ) | `admin/src/pages/manual/content.ts` |
| หน้าแสดงผลคู่มือ (ไม่ต้องแก้เวลาแก้เนื้อหา) | `admin/src/pages/manual/index.tsx` |
| ภาพหน้าจอ | `admin/public/manual/<id>.webp` (สร้างจากสคริปต์ ห้ามแก้มือ) |
| สคริปต์ถ่ายภาพ + วงเลข + ข้อมูลสมมติ | `scripts/manual-shots/` (อ่าน `README.md` ที่นั่นก่อน) |

## เมื่อไรต้องทำ

ทำเมื่อการแก้ไขในรอบนั้นมีอย่างใดอย่างหนึ่งต่อไปนี้ (ถ้าแค่แก้ bug หลังบ้านหรือแก้สีเล็กน้อย ไม่ต้อง):

- เพิ่ม / ลบ / เปลี่ยนชื่อ / ย้ายตำแหน่ง ปุ่ม ช่องกรอก แท็บ เมนู การ์ดสรุป ใน `admin/src/pages/**` หรือ `components/layout/**`
- เพิ่มหน้าใหม่ หรือ route ใหม่ใน `admin/src/App.tsx`
- เปลี่ยนขั้นตอนของ flow เช่น **login** (หน้า `pages/login`, การ redirect, ลืมรหัสผ่าน, บัญชี Super Admin), ฟอร์มหลายขั้น (เพิ่มพนักงาน/สาขา), การอนุมัติ, ปุ่มส่งออก
- เปลี่ยนกติกาธุรกิจที่คู่มืออธิบายไว้ (เช่น โควต้าจอง/ลา, เพดาน OT, ใครแก้ผู้ใช้ได้)
- เปลี่ยนหน้าตาจนวงเลขในภาพเดิมชี้ผิดที่ (จัด layout ใหม่ทั้งหน้า)

## ขั้นตอน

1. **หาหัวข้อที่เกี่ยวข้อง** — ค้นใน `content.ts` ด้วยชื่อหน้า/ปุ่ม/คำสำคัญ (`keywords`) ดูว่าหัวข้อไหนอ้างถึงหน้าจอที่แก้ ถ้าเป็นหน้าใหม่ที่ยังไม่มีหัวข้อ → เพิ่มหัวข้อใหม่ในหมวดที่ตรงที่สุด (หรือหมวดใหม่)
2. **แก้ข้อความ** ใน `content.ts` ให้ตรงกับระบบตอนนี้
   - `steps` = ลำดับที่ผู้ใช้กดจริง ใช้ **ตัวหนา** กับชื่อปุ่ม/ช่องตามที่เห็นบนจอ
   - `callouts` ของภาพ: เลข `n` ต้องตรงกับ `marks[].n` ใน `scripts/manual-shots/shots_def.js` ของภาพนั้น
   - `note` ใช้ tone `warn` สำหรับสิ่งที่ย้อนกลับไม่ได้/กระทบคนอื่น, `tip` สำหรับทางลัด, `info` สำหรับกติกา
   - เขียนจากสิ่งที่ **อ่านจากโค้ด/ข้อความช่วยเหลือในหน้านั้นจริง** ห้ามเดาพฤติกรรม ถ้าไม่แน่ใจให้บอกผู้ใช้ว่าส่วนไหนยังไม่ได้ตรวจ
3. **ถ่ายภาพใหม่** เฉพาะหน้าที่เปลี่ยน ตามขั้นใน `scripts/manual-shots/README.md`:
   ```
   cd admin && VITE_API_URL= npx vite --port 5199 --strictPort     # เปิดค้างไว้
   cd scripts/manual-shots && node capture.js <id> [<id> ...]      # เช่น login employee-list
   ```
   - ถ้าเพิ่มภาพใหม่: เพิ่มรายการใน `shots_def.js` (id = ชื่อไฟล์, `marks` = วงเลข) และเรียกใช้ใน `content.ts` ด้วย `img('<id>', 'คำอธิบายภาพ', [...])`
   - ถ้าหน้านั้นเรียก API ใหม่ที่ `fixtures.js` ยังไม่มี สคริปต์จะพิมพ์ `unmatched: GET ...` → เติม route ใน `fixtures.js` ด้วยข้อมูลสมมติ
4. **เปิดดูภาพทุกใบที่ถ่ายใหม่** (Read ภาพ) ตรวจว่าวงเลขอยู่ถูกปุ่ม ไม่ทับกัน และไม่มีข้อมูลจริงหลุดเข้ามา
5. **ตรวจ** `cd admin && npx tsc --noEmit` และเปิดหน้า `/manual` ค้นหาหัวข้อที่แก้ว่าขึ้นถูก
6. **รวมไว้ในคอมมิตเดียวกับการแก้หน้าจอ** (ข้อความ + ภาพ + `shots_def.js`/`fixtures.js` ถ้ามีแก้) เพื่อให้คู่มือกับโค้ดไม่เคยห่างกัน

## กฎที่ห้ามพลาด

- **ห้ามมีข้อมูลจริงในภาพ** — ภาพทั้งหมดถ่ายจากข้อมูลสมมติใน `fixtures.js` (ชื่อ/เบอร์/เลขบัตรปลอม) ห้ามถ่ายจากระบบ production หรือวางภาพจริงของลูกค้า
- หน้า login: สคริปต์ลบกล่อง "บัญชี Demo (DEV only)" ก่อนถ่าย ถ้า login เปลี่ยนโครง ตรวจว่าไม่มี username/รหัสจริงโผล่ในภาพ
- แก้ภาพ `.webp` ด้วยมือไม่ได้ผล — ครั้งหน้าที่ถ่ายใหม่จะถูกเขียนทับ ต้องแก้ที่ `shots_def.js`
- ถ้าแก้ UI **ฝั่งพนักงาน (LINE)** อย่างเดียว คู่มือแอดมินไม่ต้องแก้ (ฝั่งพนักงานมีสไลด์คู่มือแยกที่ `employee/src/components/ui/GuideCarousel.tsx` สอนเฉพาะการผูกบัญชี)
- ถ้าเพิ่มหน้าใหม่ที่คนทั่วไปควรรู้ ให้เพิ่มลงเมนูซ้าย/ลิงก์ที่เกี่ยวข้องด้วย แล้วใส่หัวข้อในคู่มือ ไม่ปล่อยเป็นหน้าลับ

## สรุปให้ผู้ใช้หลังทำเสร็จ

บอกสั้นๆ: หัวข้อไหนในคู่มือที่แก้/เพิ่ม, ภาพไหนถ่ายใหม่, และส่วนที่ **ยังไม่ได้ตรวจกับพฤติกรรมจริง** (ถ้ามี) เพื่อให้ผู้ใช้ตรวจก่อน push
